# Directives d'exécution et de sécurité pour AGY

Pour toute exécution autonome de type `/goal`, les limites opérationnelles et de sécurité suivantes s'appliquent strictement :

## Limites d'essais et seuils d'alerte
- **Boucles d'erreur persistantes :** Pas plus de 3 essais consécutifs pour corriger une même violation DRC/ERC récurrente. Si une correction géométrique échoue à résoudre le conflit ou en génère un nouveau, interrompre la boucle.
- **Actions constructives :** Pas de limite stricte sur le nombre d'actions d'enfilade de pistes, de placement ou de génération de plans de masse tant que l'exécution progresse selon le plan séquentiel et ne déclenche pas d'impasse critique.

## Comportement en cas d'impasse (Fallback matériel)
- **Interdiction de forcer les masques de cuivre :** Si une action de routage ou de placement génère des violations d'isolement répétées (ex: *Track to Via distance* ou *Board Outline*), cesser les modifications à l'aveugle.
- **Sauvegarde de l'état :** Ne jamais laisser un état de projet corrompu en mémoire cache. En cas d'arrêt sur seuil, consigner l'erreur exacte (coordonnées et type de conflit) et rendre la main à l'utilisateur.

## Environnement d'exécution Python
- **Exécution impérative via `uv` :** Tout script ou commande Python doit être lancé exclusivement avec `uv` (ex. `uv run python script.py`, `uv run script.py`). Ne jamais appeler `python` directement.
